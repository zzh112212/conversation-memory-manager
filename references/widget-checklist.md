# 终审弹窗组件规范（widget-checklist）

## 适用场景
F5 用户终审清单、F4 支线收尾三选一、挪线确认。**原生弹窗组件为默认首选**：运行时提供内联交互组件（HTML 渲染 + 预置状态/回传函数，如本环境的 show_widget + tg/ok/sendPrompt）时必须先渲染弹窗，不得先给文字清单；无此能力或渲染失败时走文本降级路径。

## 结构契约
- 每个待审单元一个**单选组**：组内按钮互为兄弟节点，父容器只放该组按钮；单元信息（编号/评分/标签/建议）作为标题写在组容器之外
- 按钮属性：`data-widget-option` + `aria-pressed="false"`，onclick 调用运行时预置单选函数（本环境为 `tg(this,'组名','值')`）
- 建议项写进按钮文字（如「保留（建议）」），初始一律**不预选**、不写初始选中样式；选中态由预置函数与宿主管理
- 末尾**唯一确认按钮**：`data-widget-confirm` + `onclick="ok()"`，整轮一次回传，置于题组下方 20px、左对齐
- 单问即定场景（如支线收尾三选一）可用 `onclick="sendPrompt('…')"` 点选直发
- 样式全内联、内容自包含、不加载外部依赖

## 样式要点（遵循宿主组件规范）
- 未选：白底 + 1px 浅灰边框 + 12px 圆角；已选：黑边框（不改动底色/字重/尺寸，AI 不自行实现选中/hover 样式）
- 主标签 14px、说明 12px；每个题组标注「单选」
- 确认按钮：黑底白字、总高 36px（line-height 34px + 水平 padding 16px）、圆角 999px

## 硬规则
- 一次组件只承载一轮终审；确认后按回传内容执行，不再追加询问
- 弹窗内不夹带与终审无关的问题
- **弹窗是主动呈现的唯一裁决界面**：对话正文不得引导用户绕开弹窗（不并列宣传「也可以打字」）；文字路径提示只写进清单文件头部
- 组件失败或用户主动改用文字回复：**文字终审等同生效，组件不是唯一入口**（回退通道，用户权利不删）
- 回传后执行 F5 原有流程：status 更新（keep/drop）、drop 移入 archive/、挪线改判、git commit

## 文本降级（回退通道：无组件能力 / 渲染失败 / 用户主动改用）
Markdown checkbox 清单：`- [ ] 1. u003 ★5 标签 —— 建议保留`，用户改 `[x]` 或口头报单元号。
