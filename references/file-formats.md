# 文件格式规范

## 命名规范

| 对象 | 格式 | 示例 |
|---|---|---|
| 主线单元 | `uNNN-HHMM-标签.md`（NNN 三位全局递增） | `u007-2231-字体试错.md` |
| 支线目录 | `branches/b-主题/`（短横线、小写） | `branches/b-字体调试/` |
| 回溯简报 | `rollbacks/r-节点nN-YYYYMMDD-HHMM.md` | `r-节点n2-20260929-2310.md` |
| 清单 | `checklist-节点nN.md`（存 .memory/ 根） | `checklist-节点n3.md` |

## unit.md 字段（frontmatter）

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| id | ✓ | uNNN | 全局唯一，写入后不改 |
| time | ✓ | YYYY-MM-DD HH:MM | 单元发生时刻 |
| pair | ✓ | 自由文本 | 如「用户→助手（含 3 次工具调用）」 |
| branch | ✓ | main / b-主题 | 挪线改判时**必须同步更新** |
| score | ✓ | 1–5 | 详见 scoring-rubric.md |
| tags | ✓ | 列表 | 2–6 字标签，2–4 个 |
| status | ✓ | 应答进行中 / 未终审 / keep / drop | 应答结束后：应答进行中→未终审；终审后→keep / drop |

正文两节：`## 原文转录`（逐字保真；工具链记「做了什么+结果一句话」；敏感信息 `[REDACTED]`）与 `## 评分依据`（一行）。
**原文转录一经写入不再修改**——修改=篡改历史，只允许追加。

## manifest.md

四节固定顺序：`当前状态`（任务/当前节点/活跃支线）、`主线链`（节点|单元|评分|标签|状态）、`分支登记`（分支|来源节点|主题|状态|收尾结论）、`回溯点`。任何单元/分支变更后同步刷新，manifest 与实际文件不一致视为事故。

## checklist.md

三节：`保留决策`（checkbox 行）、`支线收尾`（三选一建议+理由）、`处置结果`（终审执行后由 AI 填写，只记事实）。行格式：`- [ ] u001 ★5 标签 —— 建议`。

## rollback-brief.md

五节固定顺序：任务目标（截至该节点）/ 主线单元摘要链（每单元一行）/ 当时活跃支线 / 关键文件状态 / 继续指令。简报必须自包含——接收方是零上下文的新会话。

## 状态机

```
单元:  应答进行中 ──(应答结束后的自然间隙)──→ 未终审
       未终审 ──(用户终审)──→ keep（留原位）
                      └────→ drop ──→ 移入 archive/（不物理删除）
分支:  open ──→ merged（≥4分单元已摘录进主线）
        ├──→ closed（归档保留，留在 branches/）
        ├──→ deleted（单元全数移入 archive/）
        └──→ sealed（回溯封存，只读）
挪线:  用户指令 → 移动文件 → 改 branch 字段 → 刷新 manifest（随时可做，AI 无权拒绝）
```

## Git 增强命令速查（仅限 .memory/ 内部）

```bash
git init                                   # 首次（在 .memory/ 内，独立记忆仓库）
git add -A && git commit -m "归档 u001-u005"
git commit -m "终审 n3: keep×5 drop×2"     # 每次 F5 执行后
git branch b-字体调试                        # 支线收尾时
git log --oneline                           # F6 回溯定位节点
```

绝不在用户项目根执行 git；绝不触碰 `.memory/.git` 以外任何 `.git`。
