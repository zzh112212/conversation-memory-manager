# 三技能联动契约

联动是**可选增强，不是依赖**。每个契约先做特征检测；检测不到就纯对话模式运行，功能不缺。这是硬要求：生态用户可能只装本技能一个。

## C1 交接联动（↔ context-continuity）

**特征检测**：项目根存在 `.planning/` 目录。

**HANDOFF 时**（context-continuity 交接流程触发时，本技能并行执行，不打断其流程）：
1. 刷新 manifest.md 至当前真实状态；
2. 生成/更新《对话记忆管理清单》；
3. 在 `.planning/handoff.md` 末尾**追加**「## 记忆联动」节，内容三行：manifest 路径、主线 ≥4 分单元的一行摘要、待终审条数。**只追加此节，不改简报其余任何内容**（handoff 的自包含原则由 context-continuity 主导，本技能不越界）。

**RESUME 后**（新会话完成 .planning/ 恢复之后）：
读 handoff.md 的「记忆联动」节 → 默认只拉主线链与 ≥4 分单元摘要入上下文；支线一律待用户点名。这从源头控制上下文体积——支线内容不占 token，直到用户要它。

**边界铁律**：findings.md 记提炼后的事实结论，`.memory/` 记带评分的对话原文。两者互相引用（写路径），**永不复制内容**——两个真相源必然打架，打架时谁都不信。

## C2 饱和联动（↔ context-continuity）

**特征检测**：同 C1。

共用同源饱和信号（S1–S6），本技能阈值更敏感（记忆抢救比交接便宜，宁可早做）：

| # | 信号 | context-continuity | 本技能 |
|---|---|---|---|
| S1 | 轮数/工具调用 | 20 轮 / 40 次 | **15 轮 / 30 次** |
| S2 | 重复读取已读文件 | ✓ | ✓ |
| S3 | 用户复述旧要求 | ✓ | ✓ |
| S4 | 同一错误再现 | ✓ | ✓ |
| S5 | 决策漂移 | ✓ | ✓ |
| S6 | 平台压缩通知 | ✓ | ✓（**单独命中即动作**） |

- 命中 2 条 → 触发 F3 清单 + 提醒用户「可以交接了」；
- **S6 单独命中 → 立即执行 F1 兜底抢救**：压缩通知响起是原文可见的最后窗口，先转录再说话。

## C3 搁置联动（↔ input-triage）

**特征检测**：对话中存在 input-triage 的搁置区（parking-lot 文件，或对话内搁置清单）。

- **评分参考**：被 ADD/CORRECT 吸收进任务列表的插话单元 → ≥4 分（方向性裁决）；进搁置区的 ASK/NOISE → ≤2 分（收尾补答被后续引用则升 3）。
- **搁置激活开支线**：搁置区某条目被激活展开处理时 → 该主题交互开独立支线 `b-主题`——搁置的东西天然是支线，不用挤主线。
- **收尾对接**：input-triage 收尾清账时，本技能同步生成记忆清单，两件事一次收束，不再单独打扰用户。

## 降级矩阵

| 依赖 | 检测特征 | 不在时的行为 |
|---|---|---|
| context-continuity | `.planning/` 存在 | F3 按自身阈值触发；不写任何 handoff；恢复只靠 manifest |
| input-triage | 搁置区存在 | 评分纯按对话内容与四维度判断 |
| git | `git` 可执行 | 纯 markdown；回溯走 manifest 清单重建 |
